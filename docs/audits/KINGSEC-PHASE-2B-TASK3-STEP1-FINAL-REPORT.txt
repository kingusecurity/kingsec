TASK 3A — kingsec doctor
--------------------------------------------------------------------------------

Implemented as a genuine `kingsec doctor` subcommand (argparse
subparsers in __main__.py; `kingsec --host ... --port ...` with no
subcommand is unchanged). Read-only by construction: never calls
create_wired_application() (which builds a database engine and can
create the data directory) — only load_settings() + register_scanner(),
so it works before a database has necessarily been set up.

Agreement with the planner is structural, not incidental:
bootstrap/composition.py's previously-inline ExecutionPlanner
construction was extracted into a public build_execution_planner()
function, called from both the real composition root and doctor — one
place this wiring exists, not two hand-synchronized copies.
ExecutionPlanner gained read-only `discovery`/`registry` properties so
doctor reads the exact same ScannerDiscoveryService/ScannerPluginRegistry
objects the real planner decides with.

REAL BUG FOUND AND FIXED while running doctor against this host:
ScannerDiscoveryService.get_scanner_status() always included the
"download the binary" hint even once the binary was already found, and
could duplicate a hint or include one for a non-blocking optional asset
— producing a misleading "download nuclei from..." fix for a scanner
whose binary was already present (nuclei, on this exact host). Fixed at
the source (also read by the existing /scanners REST route, not just
doctor), with 3 new regression tests.

REQUIRED TEST (doctor's verdict must match the planner's real decision,
across every profile): TestDoctorAgreesWithPlanner,
tests/unit/application/test_phase2a_honest_coverage.py, parametrized
over every (profile_id, target_type) pair the real planner supports —
PASSES.

Full document: docs/audits/KINGSEC-TASK3B-ASSET-PROVISIONING-PROPOSAL.txt

Summary: nuclei-templates is ~728MB (git size), updated continuously via
nuclei's own `-update-templates` command, MIT-licensed. SecLists (the
de facto wordlist source) is ~3.6GB total, MIT-licensed at the repo
level; spot-checked one candidate file (Discovery/Web-Content/common.txt)
directly for an embedded separate license note — none found, but this
is a spot-check of one file, not an exhaustive audit of the whole
collection.

Recommend: documented one-time setup command for BOTH assets (nuclei's
own `-update-templates`, one documented wordlist URL) — not bundling.
nuclei-templates is ruled out on size/currency, not licensing (a frozen
copy goes stale within days). The wordlist case is licensing-clean to
bundle but not recommended anyway: KingSec has no special standing to
pick "the" wordlist, and `kingsec doctor` already gives the operator a
precise, actionable fix the moment either asset is missing — which is
the actual first-run pain point this task names.

`nuclei -update-templates` was never run, per explicit instruction.
