  testing the REAL repository's source rather than the clone's — an
  ambiguity worth avoiding rather than glossing over. Instead, content-hash
  equality (normalizing CRLF/LF, since Git on this Windows machine
  reports line-ending differences for every one of these files on every
  phase) was verified directly between the real repository's post-commit
  state and the clone's three Phase 30 files: all three were confirmed
  byte-identical after normalization. Given that equivalence, running the
  test suites via the real repository (now at the identical HEAD,
  `5be975a`) is evidentially equivalent to running them inside the clone
  for the purpose of validating the Phase 30 fix's correctness — the
  distinction that matters (ruff/mypy exercising the clone's own files
  directly, Sections above) was preserved precisely where import-path
  ambiguity was not a concern.
