TASK 4 — nmap port coverage disclosure
--------------------------------------------------------------------------------

Threaded ScannerResult.port_specification (recorded since Task 2, never
previously surfaced) through the same path ScannerResult.warnings
already travels: ScannerResult -> ScannerProgress -> ScannerRunSummary
-> the JSON persistence round-trip (mappers.py) -> the rendered
Limitations section.

1. Derived, never hardcoded: `_port_coverage_note()` (templates.py)
   reads `ScannerRunSummary.port_specification` directly and embeds it
   VERBATIM in the disclosure sentence for a URL target's two-invocation
   spec ("nmap's own default port sweep + explicit port N") - the
   sentence and the recorded fact cannot drift apart because the
   sentence IS the recorded fact, not a paraphrase of it.

2. Honest about what was NOT examined: every disclosure (URL or
   non-URL) ends with "a service running on a[n] [uncommon] port
   outside that [default set/coverage] would not have been seen by this
   assessment" - written for an SME reader, not a security engineer.

3. Never implies KingSec chose the ports: the non-URL case (port_
   specification is None by design - nmap's own unmodified default)
   still discloses honestly ("nmap's own default port selection"),
   attributing the choice to nmap, never KingSec.

4. REQUIRED TEST (the linkage, not fixed wording):
   TestPortCoverageDisclosure.test_disclosure_changes_with_the_recorded_specification
   (test_templates.py) renders two reports differing ONLY in
   port_specification and asserts each rendered disclosure contains its
   OWN spec text and NOT the other's - a test asserting only fixed
   wording would still pass if the derivation silently broke; this one
   would not. 4 more tests cover: no disclosure when nmap didn't run, a
   URL spec appearing verbatim, the non-URL "nmap's own default"
   attribution, and a FAILED nmap producing no default-port claim (its
   None means something different from a genuine non-URL default).

5. PDF regenerated from C:\kingsec-e2e's real, stored data (no new
   scan) - the Run #4 reference-case assessment (asmt-a7cec80b4fe542eb9
