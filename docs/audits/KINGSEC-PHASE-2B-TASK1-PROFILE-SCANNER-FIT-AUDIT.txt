================================================================================
a) WHAT EACH OF THE 9 SCANNERS ACTUALLY ASSESSES, AND WHAT IT GENUINELY NEEDS
================================================================================

nmap     — Network port/service scanner. Needs a network-reachable host
           (IP, resolvable hostname) or a CIDR range. Does not consume URLs
           directly; a URL's host (+ port) would work if decomposed.

nuclei   — Template-driven vulnerability scanner covering both raw network/
           TLS/DNS checks and full HTTP-based web checks depending on the
           template category. Genuinely usable against an IP, a hostname,
           or a URL — its declared set matches its real capability.

ffuf     — HTTP(S) content/parameter fuzzer. Genuinely needs a full URL
           (scheme + host [+ port]) to build requests against — see the
           real bug found below, its adapter does NOT construct one from a
           bare hostname.

gobuster — Same category as ffuf (KingSec runs it in `dir` mode: HTTP
           directory enumeration). Genuinely needs a full URL for the same
           reason — see the same bug below.

nikto    — Web server vulnerability scanner. Genuinely needs an HTTP(S)
           target with host/port/scheme, but its adapter correctly derives
           all three from EITHER a full URL or a bare `host[:port]` string
           — see below, this one is correctly implemented.

amass    — Subdomain enumeration (passive/active DNS, certificate-
           transparency logs, brute-forcing) of a REGISTRABLE DOMAIN.
           Genuinely needs a real domain name with a public DNS zone to
           enumerate subdomains of. See (d).

trivy    — Container image / filesystem / git-repo vulnerability scanner.
           Genuinely needs an image reference, a local filesystem path, or
           a git repo URL. This is not a network-reachable target at all —
           a fundamentally different kind of input than IP/hostname/URL.
           See (c).

zap      — Web application vulnerability scanner (proxy-based spider +
           active scan). Genuinely needs an HTTP(S) URL. Its {URL}
           declaration is correct.

semgrep  — Static source-code analyzer. Genuinely needs a local filesystem
           path to source code (a git checkout or directory) — not a
           network-reachable target at all, same category problem as
           trivy. See (c).

================================================================================
d) CAN AMASS DO ANYTHING USEFUL AGAINST AN IP OR "LOCALHOST"? NO.
================================================================================
Confirmed by design, not by running it: amass enumerates subdomains of a
registrable domain via DNS techniques (passive sources, certificate-
transparency logs, active brute-forcing). It has no operation defined
against a bare IP address at all (no domain to enumerate subdomains of),
and "localhost" is not a registrable domain — it has no public DNS zone
and therefore no subdomains to find. Checked KingSec's own HOSTNAME
validation (`domain/target.py:_validate_hostname`): it only checks
RFC 1034/1123 LABEL SYNTAX (length, allowed characters per label) — it has
no concept of "is this a real, registrable, publicly-resolvable domain."
"localhost" passes this validation as a syntactically valid single-label
hostname. So today, a HOSTNAME target of "localhost" is accepted by
KingSec, marked compatible with amass by the registry, and would run
amass against it — producing zero useful output, not because of a bug in
amass's execution, but because the target was never a domain amass could
do anything with in the first place. The registry's boolean
compatible/incompatible check cannot express this — it's a "compatible
but useless" case, not an "incompatible" one.
