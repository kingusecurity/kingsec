## Harmless No-Changes Migrations

There are **17** empty migrations (all named `*_no_changes.py`) between the last real migration (`a1b2c3d4e5f6`) and HEAD (`0363a63e0698`).

Every no-changes migration has:
- `upgrade() → pass`
- `downgrade() → pass`

They form a single linear chain with no branches. Because they execute no operations, they are **completely harmless**:

- **Upgrade**: No SQL is generated or executed.
- **Downgrade**: No SQL is generated or executed.
- **Revision graph**: Continuous and linear — no broken dependencies.
- **Database state**: Any database stamped at any revision in the chain will still upgrade and downgrade correctly.

## Why They Exist

These migrations were generated by repeated runs of `alembic revision --autogenerate` during development when no schema changes were detected. They are a development artifact and serve no functional purpose.

## Squash Recommendation

The 17 no-changes migrations SHOULD be squashed into a single no-op migration **only when the next real migration is created**. The procedure is:

1. Create a new migration that `Revises: a1b2c3d4e5f6` (the last real migration).
2. Delete all 17 `*_no_changes.py` files.
3. Verify the chain: `alembic upgrade head` and `alembic downgrade -1` should produce no SQL.

Do NOT squash pre-emptively — any production database stamped at one of the intermediate revisions would need `alembic stamp` to match the new head.
