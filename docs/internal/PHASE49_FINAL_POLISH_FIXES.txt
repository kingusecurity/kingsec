3. HAND-ROLLED PAGINATION IN 3 FRONTEND PAGES
==========================================================================

Issue: KevViewPage.tsx, CveExplorerPage.tsx, and ExecutionHistoryPage.tsx
each hand-rolled their own Previous/Next pagination markup instead of
reusing the existing shared components/ui/Pagination.tsx (already used
by AssetInventoryPage, AssessmentsPage, and AuditTable). One of them
(ExecutionHistoryPage) used raw, off-design-token bg-gray-100 in its
pagination buttons specifically.

Fix: All three now use the shared Pagination component.
  - KevViewPage.tsx: direct swap (already tracked 1-indexed page state
    in the exact shape the shared component expects).
  - CveExplorerPage.tsx: page is nested in a filter object; wired
    onPageChange to update filter.page. Preserved the "{total} total"
    label the old markup showed (the shared component doesn't include
    a total-count display) so no visible information was dropped.
  - ExecutionHistoryPage.tsx: page state was zero-indexed
    (offset = page * limit); converted at the boundary
    (currentPage={page + 1}, onPageChange maps back with -1) so the
    shared component's 1-indexed API didn't require changing the
    page's internal offset logic. Left the page's other unrelated
    bg-gray-100/bg-gray-50 usages untouched — those are a separate,
    broader design-token-drift finding not in scope for this pass.

Verified: tsc -b clean, oxlint clean, full vitest suite 265/265, no
dedicated tests existed for any of the three pages. Live-verified via a
real browser session: all three pages load with zero console errors
after login (this also incidentally re-confirmed deep-link session
persistence from the Phase 49 patch still works).
